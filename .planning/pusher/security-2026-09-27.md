## Architecture summary (what the attack surface actually is)

- Offline-only Expo app. All data lives in on-device SQLite. No network backend is called.
- "Auth" is a local display name. No passwords, no tokens, no sessions to steal.
- Outbound data flows: Sentry and PostHog, both only when their env var is set (no `.env` is committed).
- `convex/` holds backend functions that are **not deployed and not called** (no `_generated/`, no URL).
- No CI workflows, no Dockerfiles, no IaC, no webhooks, no LLM usage, no repo-local skills.
- Deep-link scheme `tonguetutor://` only reaches read-only local screens.

### 1. Convex backend has no authorization at all (latent, not exploitable today)

Every function in `convex/children.ts`, `exposures.ts`, `families.ts`, `foods.ts`, `foodChains.ts`, `users.ts` takes ids straight from args and reads/writes with no `ctx.auth` check and no family-membership check. Examples: `exposures.getByFamily({familyId})`, `children.remove({id})`, `foods.update({id,...})`, `users.getByEmail({email})`, `families.getByInviteCode({inviteCode})`.

Exploit scenario (once `npx convex deploy` runs): Convex public functions are callable by anyone who has the deployment URL, which ships inside the app bundle as `EXPO_PUBLIC_CONVEX_URL`. An attacker extracts it, then calls `families.getByInviteCode` across the 32^6 (~1.07e9) code space (codes come from `Math.random`, `src/lib/utils.ts:13`), or grabs any family/child id, and reads every child's feeding history or deletes it via `children.remove`.

Why it matters now: CLAUDE.md and NEXT_STEPS list "wire Convex" as the standing next priority. These files would go live verbatim.

Recommendation (not fixed: needs an auth design, out of scope for an autonomous session):
- Pick an identity provider (Convex Auth / Clerk) before the first deploy.
- Add a helper, e.g. `requireFamilyMember(ctx, familyId)`, that resolves `ctx.auth.getUserIdentity()` to a `users` row and checks `familyId`; call it in every handler, and for id-keyed calls (`children.get/update/remove`, `foods.*`, `foodChains.remove`) load the row first and check its `familyId`.
- Make `getByInviteCode` a rate-limited mutation that joins the caller, not a public query returning the family. Generate codes with `crypto.getRandomValues` and consider 8+ chars.
- Remove or `internalQuery`-ify `users.getByEmail`.

### 2. Sentry screenshots of minors' data — FIXED in v0.5.179

`attachScreenshot: true` since the initial commit. Any captured error sent a screenshot of whatever screen was open (child name, notes, exposure history) to Sentry. Now `false`; `src/lib/__tests__/sentry.test.ts` pins it, mutation-verified (flip back → 1 failure). Only relevant when `EXPO_PUBLIC_SENTRY_DSN` is set.

### 3. Query parameters leak into Sentry breadcrumbs (not fixed, product decision)

`DrizzleQueryError` formats its message as `Failed query: … params: <values>`. Every write handler does `console.error('Failed to …:', err)` (the deliberate v0.5.34 convention "so Sentry gets a breadcrumb"). Sentry's console integration records those as breadcrumbs, which ride along on the next reported event. A failed exposure insert therefore ships the child id, food id and free-text notes. Same vendor as #2, lower volume (only on failures).

Recommendation: add a `beforeBreadcrumb` in `initSentry` that strips everything after `params:` from console breadcrumbs (or drops the `err.message` and keeps `err.name` + stack). Not done here because it trades away debugging detail the changelog explicitly asked for.

## Checked and clean

- **Secrets:** full history (248 commits) searched for AWS/GitHub/Slack/Stripe/OpenAI/PostHog/Sentry-DSN/Convex/JWT/private-key patterns and for any ever-tracked `.env`, key, or credentials file. Only `.env.example` with placeholders (plus a removed `SENDY_*` placeholder pair). `.gitignore` covers `.env*`, keys, keystores, `google-services.json`. `password123` hits are test fixtures.
- **Injection:** only two `sql\`\`` template uses (`app/(tabs)/index.tsx:63`, `src/lib/merge-foods.ts:81`), both drizzle-parameterized with no user strings. No raw SQL concatenation, no `eval`, no WebView, no HTML rendering. CSV export already defangs formula injection (v0.5.86).
- **PostHog:** `captureEvent`/`identifyUser` have no callers.
- **Dependencies:** `npm audit --omit=dev` = 14 moderate, 0 high/critical. All are the build-tooling / no-patch-published set documented in the v0.5.165 and 2026-09-09 audit. `uuid` bounds-check advisory needs the `buf` arg; the app calls `uuidv4()` with none, so not reachable. `package-lock.json` is still gitignored (resolution floats per install) — recorded previously, still stands.
- **Local AuthN/AuthZ:** by design there is none; everything is single-device. The invite-code join only searches the local DB, so it cannot reach another device's family.
