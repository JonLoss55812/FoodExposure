# TESTS — 2026-10-28 (v0.5.238)

Baseline: 1118 tests / 72 suites green, `tsc --noEmit` clean.
After: 1119 tests / 72 suites green, `tsc --noEmit` clean. No app code changed.

## Method

The core library code (`src/lib/**`) is ~99% covered and already has real-SQLite tests for
the destructive helpers (`cascade-sqlite.test.ts`), so another coverage pass would not tell
us much. The risk is on the screens: every write handler holds a `createInFlightLatch()`, and
a latch that is never released makes the button stop responding with no error. So I deleted
each of the 30 `*Latch.release()` calls in `app/` one at a time and ran that directory's
tests (script: sed out the call on line N, run jest, restore).
