## Checked and clean

- **Secrets:** I grepped the full history (all branches) for added lines matching AWS, Stripe live, GitHub PAT, Slack, PostHog `phc_`, Sentry DSN, Convex URL and private-key patterns. The only hit is the commented placeholder in `.env.example`. No `.env`, key, keystore or `google-services` file is tracked, and `.gitignore` covers all of them.
- **Injection:** no string-built SQL, `eval`, `new Function`, WebView or HTML rendering in `app/` or `src/`. CSV cells go through `csvEscape`, whose formula guard applies to every string column.
- **AuthN/AuthZ (local):** there is no server. Every on-device read and write a route param or a persisted selection can steer is now family-scoped (see above).
- **Supabase/RLS:** not applicable. The project has no Supabase.
- **CI/CD, containers, IaC, webhooks, LLM usage, repo-local skills:** none exist.
- **PostHog:** `captureEvent` and `identifyUser` still have no callers, and there is no autocapture provider.
- **Dependencies:** `npm audit --omit=dev` reports 45 advisories (21 moderate, 24 high, 0 critical). All of them trace to the same no-fix roots recorded in v0.5.204: `braces`, `node-forge`, `sprintf-js` and `decode-uri-component`, propagated up through `expo`, `react-native`, `expo-router` and `@sentry/react-native`. The 24 "high" entries are those propagations, not new advisories. Every "fix" npm offers is a major downgrade or upgrade (e.g. `expo@44`, `@sentry/react-native@5.15`). None of the vulnerable functions is in the app's runtime path: `node-forge` is CLI dev-cert tooling, and `braces`/`sprintf-js` are Metro/build tooling. So there is no change in real exposure. (The count differs from v0.5.204's 59 because of npm's per-install resolution. `package-lock.json` is gitignored, as recorded before.)

## Below the gate (noted, not reported as findings)

- Android `allowBackup` defaults to true under Expo, so the SQLite database is included in the user's own device or cloud backup. That backup sits in the user's own account, and `adb backup` needs an unlocked device. There is no third-party exploit path.
- The Sentry redaction stops at the first `\n    at ` line. A note that itself contains that text could leak whatever follows it. Only the parent's own text can trigger this, and only when a DSN is configured. Confidence that it matters is low.
