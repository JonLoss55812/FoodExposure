# Frontend fix — 2026-11-16 (v0.5.268 → v0.5.270)

Baseline: 1225 tests / 77 suites passing, `tsc --noEmit` clean.
After: 1228 tests / 77 suites passing, `tsc --noEmit` clean.

Earlier frontend sessions (2026-10-05, 2026-10-26) had already covered accessible names,
input labels, contrast and the header tap targets. A grep sweep confirmed that: every
`TextInput` has an `accessibilityLabel`, every `Pressable` has an `accessibilityRole`, and
placeholders use the `textTertiary` token. The two problems below were still open, both
on the Log Exposure form, which is the app's main write path.

## Fixed

### 1. The stage picker overflowed a 360px phone (v0.5.269)

`StageIndicator` at `lg` size draws six fixed 56px dots with 4px gaps, 356px in all. The
Log form pads 16px on each side:

| Screen width | Content width | Overflow |
|---|---|---|
| 360 (most common Android) | 328 | 28px, so the Eat dot is clipped at the screen edge |
| 375 (iPhone SE/mini) | 343 | 13px, which runs into the right padding (16px on the left, 3px on the right) |

Fix: the md/lg dots keep their width but can shrink (`flexShrink: 1`, `maxWidth: '100%'`).
The interactive `Pressable` around each dot also gets `flexShrink: 1`. At 360px the dots
narrow to about 51px. "Tolerate" at 12px semibold is about 47px wide, so the labels still
fit, and they already had `numberOfLines={1}`. Nothing changes on screens where the row
already fit. +1 test. It is mutation-checked against reverting the component and against
removing only the Pressable style.

### 2. Four Log-form tap targets were under 44pt (v0.5.270)

| Control | Before | Notes |
|---|---|---|
| Food chips | 39px | tapped on every log |
| "Add More Details (optional)" toggle | 35px | |
| Empty-foods call to action | 35px | |
| "+ Add New" link | ~20px | text only |

Each now has `minHeight: 44` and `justifyContent: 'center'`, the same pattern v0.5.233
used for the header links. The Add New link also has `marginVertical: -8`, so the taller
target adds about 6px to the header row instead of 24px. +2 tests. Removing any one of
the four `minHeight`s makes a test fail.

## Verification
